# Binance Average Price Service

Сервис по расписанию запрашивает среднюю цену торговой пары у Binance
`/api/v3/avgPrice`

Сохраняет её в PostgreSQL и отдаёт через REST: последнюю сохранённую запись, среднюю цену за выбранный период,
все полученные записи с пагинацией, а так же рассчитывает тренд на основе этих записей.

## Стек

Java 21, Spring Boot 3.5, Spring Data JPA, PostgreSQL 16, Liquibase, MapStruct, Maven.
Тесты: JUnit 5, Mockito, Testcontainers.

## Старт
Для старты необходимы Docker и Docker compose.

Необходимо скопировать данные из .env.example в .env.
```bash
cp .env.example .env  
```   
После чего можно запустить docker compose командой:
```bash
docker compose up --build
```

Сервис будет доступен на `http://localhost:8080`,
PostgreSQL на `localhost:5433`.

Для остановки приложения `docker compose down`.
Если необходимо сохранить данные `docker compose down -v`

## Переменные окружения

`BINANCE_POLL_INTERVAL` — Пауза между опросами Binance в формате ISO-8601(`PT30S`,`PT1M`) Минимальное значение 1 секунда. По умолчанию: `PT30S`.

`BINANCE_POLL_SYMBOL` — Торговая пара, которую опрашивает планировщик. По умолчанию: `BTCUSDT`.

`BINANCE_URL` — Базовый URL для API Binance. По умолчанию: `https://api.binance.com`.

`BINANCE_RATE_LIMIT_BACKOFF` — Пауза опроса при ответе 429/418, если Binance не прислал `Retry-After`. По умолчанию 1 минута (`PT1M`).

`DB_HOST` — Хост PostgreSQL. По умолчанию: `postgres`.

`DB_PORT` — Порт PostgreSQL. По умолчанию: `5432`.

`DB_NAME` — Имя БД. По умолчанию: `tradingpair`.

`DB_USER` — Пользователь БД. По умолчанию: `postgres`

`DB_HOST_PORT` — Порт PostgreSQL на хосте. По умолчанию: `5433`

`APP_PORT` — Порт приложения на хосте. По умолчанию: `8080`

`POSTGRES_MEM_LIMIT` — Лимит памяти контейнера БД. По умолчанию: `512m`

`APP_MEM_LIMIT` — Лимит памяти контейнера приложения. По умолчанию: `1g`

## REST API

Базовый путь: `/api/v1/prices`.

Параметры `from` и `to` — момент времени в формате ISO-8601 **в UTC с суффиксом `Z`**,
например `2026-09-01T00:00:00Z`. Границы включаются, `from` должен быть строго меньше `to`.
Необязательный параметр `symbol` (5–20 символов `A–Z0–9`) по умолчанию равен `BINANCE_POLL_SYMBOL`.

Параметр `symbol` необходим для того, если в БД уже будут существовать какие-то данные о цене другой торговой пары
полученной от Binance. Если в запросе его не указавать будет выбрано значение по умолчанию.
### 1. Последняя сохранённая запись

```
GET /api/v1/prices/latest[?symbol=BTCUSDT]
```

```bash
curl http://localhost:8080/api/v1/prices/latest
```

```json
{
  "symbol": "BTCUSDT",
  "price": "76000.2500000000",
  "fetchedAt": "2026-09-10T12:00:00Z"
}
```

`price` отдаётся строкой, чтобы не терять точность. `fetchedAt` — время получения записи
от Binance, UTC, с точностью до секунды.

### 2. Средняя цена за период

```
GET /api/v1/prices/average?from=...&to=...
```

```bash
curl "http://localhost:8080/api/v1/prices/average?from=2026-09-01T00:00:00Z&to=2026-09-30T23:59:59Z"
```

```json
{ "averagePrice": 75800.1234567890 }
```

Среднее считается в БД по `NUMERIC` и округляется до 10 знаков (`HALF_UP`).
Для большинства криптовалют 10 знаков после запятой будет достаточно. Исключение составляют токены ERC-20
и "мем-коины".

### 3. Записи за период с пагинацией

```
GET /api/v1/prices?from=...&to=...&page=0&size=20
```

`page` по умолчанию `0`, `size` по умолчанию `20` (от 1 до 100). Сортировка: от новых к старым.

```bash
curl "http://localhost:8080/api/v1/prices?from=2026-09-01T00:00:00Z&to=2026-09-30T23:59:59Z&page=0&size=2"
```

```json
{
  "items": [
    { "symbol": "BTCUSDT", "price": "76000.2500000000", "fetchedAt": "2026-09-10T12:00:30Z" },
    { "symbol": "BTCUSDT", "price": "75999.9000000000", "fetchedAt": "2026-09-10T12:00:00Z" }
  ],
  "page": 0,
  "size": 2,
  "totalElements": 135,
  "hasNext": true
}
```

### 4. Тренд за период

```
GET /api/v1/prices/trend?from=...&to=...
```

```bash
curl "http://localhost:8080/api/v1/prices/trend?from=2026-09-01T00:00:00Z&to=2026-09-30T23:59:59Z"
```

```json
{
  "symbol": "BTCUSDT",
  "start_date": "2026-09-01T00:00:00Z",
  "end_date": "2026-09-30T23:59:59Z",
  "trend": "UPWARD"
}
```

Значения `trend`: `UPWARD`, `DOWNWARD`, `FLAT`.

Алгоритм: записи периода сортируются по времени и делятся пополам (при нечётном числе
лишняя запись попадает во вторую половину). Сравниваются средние цены половин:

- разница не больше 0,05 % от среднего первой половины — `FLAT`;
- среднее второй половины выше — `UPWARD`;
- иначе — `DOWNWARD`.

Для расчёта нужно минимум 2 записи в периоде.

Для ускорения фильтрации и сортировки записей по времени, а также обеспечения целостности данных, в базу данных добавлен составной уникальный индекс на основе полей `symbol`и `fetched_at`

### Ошибки

Ошибки возвращаются в формате `RFC 9457 Problem Details:`

```json
{ "status": 404, "detail": "Trading pair with symbol: BTCUSDT not found" }
```
Код ошибки: `400`. Нет обязательного параметра, неверный формат даты, `from >= to`, неверный `symbol`, `page`/`size` вне диапазона. Для ошибок валидации в ответе есть поле `invalid_fields` |

Код ошибки: `404`. Нет данных: для `latest`, пустой период в `average`, меньше 2 записей в `trend` |

Код ошибки: `500`. Непредвиденная ошибка (детали только в логах) |

## Как работает сбор данных

- Планировщик (`@Scheduled`, `fixedDelay`) вызывает Binance с интервалом `BINANCE_POLL_INTERVAL`.
  Если Binance недоступен, вернул ошибку или некорректный ответ, текущий опрос пропускается,
  в лог пишется причина, расписание продолжает работать. Запись при этом не создаётся.
- Ответы `429` и `418` (лимиты Binance) приостанавливают опросы: на время из заголовка
  `Retry-After`, а если его нет, на `BINANCE_RATE_LIMIT_BACKOFF`.
- Другие `4xx` (например, неверная пара) и `5xx` не приостанавливают опросы, они логируются.
- Запись имеет `fetchedAt`, округлённое до секунды. В БД есть уникальный индекс
  `(symbol, fetched_at)`: повторная вставка той же записи пропускается, а не падает.
- Таймауты HTTP-клиента: соединение 2 с, чтение 5 с.
- Цены хранятся как `NUMERIC(24,10)` и обрабатываются через `BigDecimal`.
- Схема БД создаётся Liquibase при старте, Hibernate её только валидирует.

## Тесты

```bash
mvn test
```

Интеграционные тесты поднимают PostgreSQL через Testcontainers, поэтому нужен запущенный Docker.
Юнит-тесты (сервис, клиент Binance, планировщик) Docker не требуют.

